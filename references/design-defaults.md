# Design defaults

Apply these defaults to new design work and check them on the rendered page. Follow project-specific visual requirements when the brief calls for a particular treatment. Keep facts and proof verifiable.

| Check | Default |
| --- | --- |
| Buttons | Give the action a clear verb. Use arrows where they communicate direction, such as next, previous, expand or open externally. Leave redundant arrows off repeated calls to action. |
| Separators | Use spacing, line breaks, or ordinary punctuation. Avoid strings of words divided by little middle dots. |
| Headline framing | Use an eyebrow only when it adds context the headline needs. Skip pills above headlines and decorative section numbering. Label a sequence by number when the order matters to the task. |
| Headline type | Give the headline a coherent treatment. Avoid a single italic word as decoration. Choose a typeface for the subject and the available font files. Skip Instrument Serif as a default. |
| Ground and accents | Use a project-specific color or a neutral ground. Skip default cream backgrounds, blurry glows behind the hero, decorative colored left borders and dithering. A deliberate material treatment, chart key or state indicator should have a concrete job. |
| Icons and status | Use meaningful symbols. Remove decorative sparkle icons and pulsing green dots. Communicate live status with a readable label and use a static indication when available. |
| Composition | Let sections use the page grid and spacing. Group things in cards when they are comparable objects or need a shared boundary. Avoid putting every section in a card and avoid the generic three-across row of icons and headings. |
| Copy | Cut the words “quiet” and “real” when used as padding. Replace strings of two-word sentences with a complete thought. Keep short functional labels when they tell someone what they can do. |
| Proof | Trace stats, ratings and outcomes to supplied or verifiable sources. Omit unsupported claims. Identify simulated data where a visitor could mistake it for evidence. |
| Scroll and motion | Show content in its settled, readable state as it enters the viewport. Skip blanket fade-on-scroll. Use motion for changes in selection, hierarchy, space or feedback. A static page is a valid choice. |

Inspect the first screen, the main action, the transitions and two successive sections at desktop and phone widths. Read headings and copy aloud. Use automated findings as evidence and check visual composition, meaning and claim provenance with a human-readable pass.
