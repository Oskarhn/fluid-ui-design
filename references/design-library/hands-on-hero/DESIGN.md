# Hands-on hero

Use for a tool with a short input that can produce a real or clearly labeled sample. Help a visitor choose an input with concrete examples in the same domain.

- **Composition** — place the headline and task field close together. Give the field room to remain usable on mobile and place the result near it in document order. If a background shows the product universe, preserve a calm area behind the form.
- **Look** — take visual cues from the tool's output, such as field notes, spectra or line work. Use one strong display size and plain controls with their own labels. Distinguish sample suggestions from primary actions.
- **Interaction** — choosing an example fills the input and leaves it editable. Submit explicitly to produce a result. Keep input text on error and state where any real request would be sent. Avoid spending budget or publishing outputs merely by choosing an example.
- **Fallback** — use a safe local preview where backend functionality is outside scope. Mark what is demonstrated. A keyboard user can navigate, edit and reset the result without needing pointer-specific motion.
- **Check** — verify an empty input, a preset, a custom value and repeated submission. Keep active UI and feedback legible even if visual media fails.

Study input: [Lucky Air Balloon's public example prompts](https://luckyairballoon.com/), discovered via [SEESAW](https://www.seesaw.website/websites/luckyairballoon).
